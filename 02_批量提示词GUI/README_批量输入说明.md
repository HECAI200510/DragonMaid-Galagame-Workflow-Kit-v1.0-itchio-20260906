# 龙女仆 ComfyUI Markdown 批量提示词工具 V2

现在可以直接选择任意兼容的 ComfyUI 工作流，并导入按编号编写的 Markdown：

```text
1. 第一张图的提示词，可以很长
   下一行仍属于第一张图

2. 第二张图的提示词

3、第三张图的提示词
```

工具会把一个编号识别成一张图。编号不必连续；下一编号出现前的多行文字都会归入上一张图。
同一行写成 `1.第一张，2.第二张，3.第三张` 也能识别。

这个工具解决的是：每个角色有一段固定身份提示词，后面有很多已经写好的动作、神态或分镜提示词，不想逐条复制到 ComfyUI。

## 最快使用方法

1. 先启动 ComfyUI，默认地址为 `http://127.0.0.1:8188`。
2. 双击桌面上的“龙女仆批量提示词输入器”；入口使用 VBS + `pythonw.exe`，不会出现 Python 黑框。`启动批量提示词输入器.cmd` 仅作为备用。
3. 选择工作流 JSON，点击“检查并读取提示词栏”。
4. 导入 `.md` 或 `.txt`；推荐使用 `1. ...`、`2. ...` 编号格式。
5. 可分别填写“所有图片统一添加到开头”和“所有图片统一添加到末尾”，再选择写入六栏面板中的哪一栏。
6. 先点“查看前 5 条拼接结果”。
7. 设定每个编号的出图数、种子和输出前缀，再点击“开始批量加入 ComfyUI”。

## 提交与生成互不锁定

- 工具只把任务快速写入 ComfyUI，不再等待上一批图片生成完成。
- 写入结束后界面立即恢复可用，可以继续导入、编辑或准备下一组提示词。
- ComfyUI 在自己的队列中继续生成，工具不会长期显示“任务仍在运行”。
- “停止当前提交”只中止尚未写入的项目，不会删除已经进入 ComfyUI 的任务。
- 已删除旧版“每200个分批等待”功能，避免后台线程长期占用工具。

## 批量查找、替换与删除

- “查找全部”会选中所有命中行，并显示命中条数和出现次数。
- “全部替换”只修改工具内存中的提示词列表，不会改写原始 MD。
- “删除匹配文字”删除每条提示词内命中的词语。
- “删除命中条目”删除整条提示词，执行前会再次确认。

## 双人／双 Markdown 模式

1. 选择双人区域控制工作流的 API 版 JSON，点击“检查并读取提示词栏”。
2. 用“导入角色A MD/TXT”载入第一名角色的提示词。
3. 用“导入角色B MD/TXT”载入第二名角色的提示词，工具会自动开启双人模式。
4. 角色A写入栏选择“角色A 左侧”，角色B写入栏选择“角色B 右侧”；识别到标准标题时会自动选择。
5. 两份文档都使用 `1. ...`、`2. ...` 编号。工具严格按编号配对，而不是盲目按行数拼接。
6. 若存在缺号或重复编号，预览和提交都会停止并列出问题，避免两个人的动作串位。
7. 共同画面、人数、互动关系和镜头提示词保留在工作流的“共同画面”节点中，不会被两份角色 MD 覆盖。
8. 可分别设置角色A和角色B的统一开头／末尾；种子、重复次数、输出目录和每批200个逻辑保持同步。
9. 顶部需要分别选择角色A和角色B；只要任意一边选择小蓝，该角色对应提示词都会执行 SFW 检查。

随工具附带的可直接批处理版本：`08_双人CG_官方区域控制_批处理API.json`。

## 连续编号自动归一化

- 导入严格连续的 `101～200`、`201～300` 等序列时，可以按当前顺序重排成 `1～100`。
- 工具提供“角色A从1重新编号”“角色B从1重新编号”和“智能识别并对齐A/B”三个按钮。
- 如果两份文档各有100条，哪怕编号分别是 `1～100` 和 `101～200`，智能对齐后都会变成 `1～100`。
- 如果角色A文件包含完整 `1～200`，而角色B文件正好是后半组 `101～200`，工具会识别为两角色分组：A取前100条，B取后100条，再分别编号为 `1～100`。
- 自动修复只在编号严格连续、数量关系明确时执行；跳号、重复编号或混合编号不会被擅自改写。
- 所有重新编号只影响当前工具内存，不会保存或覆盖原始 MD。

## 三人及更多角色、九宫格位置

- 双人模式下可以为角色A、角色B分别选择：左上、中上、右上、左中、正中、右中、左下、中下、右下。
- 点击“＋ 管理扩展角色 C～F”，可以继续添加第三至第六名角色；每人分别选择角色、九宫格位置并导入一份编号 MD。
- 工具会动态生成区域控制链，而不是把“左上”等位置词简单塞进提示词。
- 每名角色都会获得独立的 `CLIPTextEncode → ConditioningSetAreaPercentage → 区域LoRA Hook → 条件合并` 链。
- 每个区域使用对应角色的推荐 LoRA，角色提示词只作用于该区域，最后再与共同画面条件合并。
- 所有 MD 都按角色A的编号严格对齐；任何一份缺号或重复编号都会阻止提交。
- 九宫格区域允许有重叠，适合拥抱、牵手或前后遮挡；角色越多，身份和肢体保真难度越高。
- 当前限制为 2～6 人。1216×832 下通常建议 2～3 人；4～6 人适合群像远景，不建议要求复杂肢体接触。

## 六栏面板兼容

- 自动识别：通用、表情、动作、形象、穿着、分镜。
- 默认写入“通用提示词”，同时保留工作流原有的身份、服装和分镜栏。
- 前置和后置内容只在生成任务时拼接，不会修改原始 Markdown。
- 若导入的是纯动作或纯表情，可以在下拉框中改为相应栏目。
- 普通 `CLIPTextEncode` 工作流也支持，会自动列出非负面的文本编码节点。
- 遇到工具不能转换的自定义节点，请在 ComfyUI 中导出 `API Format` JSON 后再选择。

## 支持的提示词文件

- TXT / MD：默认每个空行分隔一条提示词。
- CSV：自动识别 `角色`、`具体提示词`、`后半段`、`提示词`、`prompt`、`suffix` 等列名。
- JSON：支持字符串列表，或包含 `prompt` / `suffix` / `提示词` 字段的对象列表。
- “导入七角色目录”：按文件名中的管家、小红、小绿、小蓝、小粉、小金、小黑或英文别名自动归类。

## 工作流兼容性

- 默认附带的七个工作流可直接使用。
- 其他只使用 ComfyUI 核心节点的 UI 工作流通常可以自动转换。
- 含自定义节点的复杂工作流，请在 ComfyUI 设置中开启开发者模式，导出 `API Format` JSON，再在工具里选择该文件。

## 不会做的事情

- 不修改原始工作流和原始提示词文件。
- “停止当前提交”只停止尚未提交的任务，不会删除已经进入 ComfyUI 队列的任务。
- 小蓝始终只允许 SFW；工具检测到明显成人词时不会提交小蓝任务。

## 输出与记录

- 图片仍保存在 ComfyUI 的 output 目录，子目录由“输出前缀”控制。
- 每次批量提交都会在 `runs` 目录生成 `run_manifest.json`，记录角色、完整提示词、种子、输出前缀和 ComfyUI prompt ID。
- “导出任务包（不生图）”可以先生成每条任务的 API JSON，供检查或以后复跑。
