# 剧本机制与 UX 迭代

## 作者职责

本项目的剧本主体、角色顺序、分支构想、功能需求和 UX 体感判断由作者提出。AI/代码工具参与资料整理、提示词草拟、实现、检查和版本迭代。公开说明应保留这个分工，不写成“AI 自动生成了整个游戏”，也不把工具实现写成作者没有参与的黑盒。

## 当前代表性流程

```text
序章/规则
-> 当前角色普通路线
-> 分支出现并保存选择前检查点
   -> 继续挑战：跳过该角色战败支线，进入下一位
   -> 承认战败：播放当前角色支线
      -> 结算
      -> 一键回到刚才的抉择
```

## 分支自动存档

- 与 1～6 号手动存档分离；
- 分支界面出现时保存“尚未选择”的状态；
- 到下一个分支时覆盖为最新检查点；
- 进入/结束战败支线不会清掉该检查点；
- 读档窗口有独立卡片；
- 战败结算页有直接回读按钮；
- 标题页和分支界面明确提醒玩家。

已有技术证据覆盖 5 个分支点：`guanjia`、`xiahei`、`xiaolv`、`xiaofen`、`xiaohong`。这是一种改善“为了看支线不得不手动存档”的 UX 方案，不是通用 Galgame 标准。

## UX 版本演进

根据现有 v1.7～v2.1 文件和验收记录，可归纳为：

- v1.7：日语正式配音接入与基础验证；
- v1.8：中/英/日界面与剧情包切换、JSON 导入；
- v1.9：配音/纯音效模式、12 个程序化 SFX、Credits；
- v2.0：CC0 音效替换/补充、音频来源与署名整理；
- v2.1：65 条 Qwen3-TTS 情绪语音、92/92 场景映射、142 个绑定；
- v2.1 后续副本：独立分支自动存档、战败结算回读、桌面/手机响应式复查。

这里的版本是工作副本的迭代轨迹，不表示每一版都已公开发行。

## 体感驱动但要留下证据

“玩起来不顺”可以触发设计修改，但修改后要变成可验收行为：

- 玩家是否看得见选项已自动保存；
- 支线结束后是否能一键回到选择前；
- 手动存档是否没有被自动档占用；
- 390 px 是否横向溢出；
- 对话、分支和结算时 CG 是否被 UI 遮挡；
- 中文/英文/日语切换后控件是否重绘；
- 音频模式是否真的改变播放优先级。

现有浏览器验收覆盖 Chrome、1440 px 桌面与 390 px 手机宽度；它不等于完整人工通关或所有浏览器/设备验收。
